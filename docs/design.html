Colin’s Balance

Load balancer simulation: design document

Flow diagram

This shows how a request moves through the program. The dashed box repeats every clock cycle.

Gray: setup and reporting. Orange: firewall. Blue: switch. Green: load balancer (one each for S and P).

Description

The goal is to keep each load balancer’s queue between 50 and 80 requests per server.

Setup

  1. Read the settings from config.txt and the command line: number of servers, run time, wait time n, firewall IP ranges, and verbose or quiet mode.
  2. Create two load balancers, one for streaming (S) jobs and one for processing (P) jobs, and split the starting servers between them.
  3. Fill each balancer’s queue with its servers × 100 random requests.

Every clock cycle

  1. With some chance, one or more new random requests are created, each with an IP in, IP out, time and job type (P or S).
  2. The firewall checks the source IP against the blocked ranges. Blocked requests are dropped and logged.
  3. The switch sends S requests to the streaming balancer and P requests to the processing balancer, where they wait in that balancer’s queue.
  4. Each busy server counts down its time. When a server finishes, it asks for the next request.
  5. Each balancer removes a server if its queue is under 50 × servers, or adds one if it is over 80 × servers. After a change it waits n cycles before checking again. A server being removed finishes its current request first, so no work is lost.
  6. Write the events to the log and add 1 to the clock.

End

When the clock reaches the run time, the program prints a final summary to the screen and the log file for each balancer and for both combined: requests processed, blocked and left in the queue, plus the server counts.
